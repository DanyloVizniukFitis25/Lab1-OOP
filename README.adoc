== Мета роботи

Отримати практичні навички розробки програм з використанням класів
та інтерфейсів у мові Java.

== Варіант завдання

*Варіант 2* -- розробити модель *поштової скриньки*.

Обрана математична задача -- *№9. Сортування бульбашкою*: реалізувати
алгоритм сортування бульбашкою для масиву чисел з підрахунком
кількості обмінів елементів.

== Опис предметної області

Модель описує роботу поштової скриньки: до неї листоноша доставляє
різні типи поштових відправлень (звичайні листи, рекомендовані листи,
посилки), власник скриньки отримує сповіщення про кожне нове
відправлення, а частину відправлень можна відстежувати за трек-номером.

== Опис класів та інтерфейсів

=== Інтерфейс `Trackable`

Визначає контракт для відправлень, які можна відстежувати: отримання
трек-номера, поточного статусу та його оновлення. Реалізований у
класах `RegisteredLetter` та `Parcel`.

[source,java]
----
public interface Trackable {
    String getTrackingNumber();
    String getStatus();
    void updateStatus(String newStatus);
}
----

=== Інтерфейс `Notifiable`

Визначає контракт для сутностей, здатних сповіщати власника про подію.
Реалізований у класі `Mailbox`.

[source,java]
----
public interface Notifiable {
    void notifyOwner(String message);
}
----

=== Клас `MailItem` (рівень 1, abstract)

Базовий абстрактний клас усієї ієрархії відправлень. Зберігає
відправника, отримувача та вагу; оголошує абстрактний метод
`getType()`.

=== Клас `Letter` (рівень 2)

Спадкоємець `MailItem`. Додає поле `pageCount` (кількість сторінок).

=== Клас `RegisteredLetter` (рівень 3)

Спадкоємець `Letter`, найглибший клас ієрархії. Додає трек-номер і
статус, реалізуючи інтерфейс `Trackable`.

=== Клас `Parcel` (рівень 2)

Спадкоємець `MailItem`. Посилка з описом вмісту, також реалізує
`Trackable`.

=== Клас `Mailbox`

Поштова скринька: зберігає адресу, власника (`MailboxOwner`) та список
відправлень `List<MailItem>`. Реалізує `Notifiable` -- при додаванні
нового відправлення власник отримує сповіщення в консоль.

=== Клас `MailboxOwner`

Проста сутність-власник скриньки: ім'я та телефон.

=== Клас `Postman`

Листоноша, що доставляє відправлення (`MailItem`) у конкретну
`Mailbox` та (якщо відправлення `Trackable`) оновлює його статус на
"доставлено".

=== Клас `MailStatistics` -- математична задача

Реалізує сортування бульбашкою з підрахунком кількості обмінів:

* для "чистого" масиву чисел `double[]` (як того вимагає умова задачі);
* для масиву відправлень `MailItem[]` -- сортування за вагою, з тією
  самою логікою підрахунку обмінів.

[source,java]
----
public static int bubbleSort(double[] arr) {
    int swaps = 0;
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {
        boolean swappedInPass = false;
        for (int j = 0; j < n - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                double temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
                swaps++;
                swappedInPass = true;
            }
        }
        if (!swappedInPass) break;
    }
    return swaps;
}
----

=== Клас `Main`

Демонструє повний сценарій: створення власника й скриньки, доставку
трьох різних типів відправлень листоношею, виведення вмісту скриньки,
підрахунок загальної ваги та сортування бульбашкою (як масиву
відправлень, так і "чистого" масиву чисел).

Повний код усіх класів -- у директорії link:src/postoffice/[`src/postoffice`].

== Висновок

У ході виконання лабораторної роботи побудовано ієрархію класів
Java-моделі поштової скриньки глибиною 3 рівні (`MailItem` ->
`Letter` -> `RegisteredLetter`), реалізовано два інтерфейси
(`Trackable`, `Notifiable`) та інтегровано їх у загальну модель.
Додатково реалізовано математичну задачу -- сортування бульбашкою з
підрахунком кількості обмінів -- і застосовано її як до масиву чисел,
так і до масиву об'єктів моделі (сортування відправлень за вагою).
Отримано практичні навички проєктування класів, успадкування,
абстрактних класів та інтерфейсів у Java.
